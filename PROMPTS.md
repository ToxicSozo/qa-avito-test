
## 1. Разбор требований

```text
Прочитай ТЗ Авито и коллекцию Postman. Собери проверки для всех восьми операций API. Сверь методы, версии маршрутов, статусы и поля ответов. Отметь требования и допущения отдельно.
```

## 2. Тест-кейсы

```text
Оформи TESTCASES.md. Для каждого кейса укажи ID, предусловия, шаги и ожидаемый результат.
Покрой штатные сценарии, ошибки, границы и переходы состояния. Для счётчиков проверь -1, 0 и 1. Однотипные проверки параметризуй.
```

## 3. Автотесты и данные

```text
Напиши автотесты на Python, pytest и requests. Разложи тесты по операциям. Вынеси HTTP-клиент, фикстуры и общие проверки.
Генерируй уникальные данные. Получай sellerID и Bearer-токен от API. После теста удаляй созданные объявления, даже если проверка упала.
Убери офлайн-тесты. Группируй проверки по операциям API. Сохрани ID тест-кейсов.
```

## 4. Проверка покрытия

```text
Сверь решение с ТЗ и найди пробелы. Для создания и удаления без токена проверь HTTP 401 и состояние данных после отказа.
Сверь владельца сохранённого объявления с учётной записью. Проверь, что сообщения об ошибках цены и пароля объясняют причину.
Проверь жизненный цикл целиком. Зарегистрируйся, войди, создай объявление, прочитай его и статистику обеих версий, затем удали.
```

## 5. Баг-репорты и отчёт

```text
В BUGS.md укажи шаги, ожидаемый и фактический результат, серьёзность и окружение. Свяжи падения с ID дефектов.
Добавь самодостаточный HTML-отчёт через pytest-html. Покажи подготовку, проверку и очистку. Приложи JSON с HTTP-диагностикой и ID бага. Исключи токены и пароли.
```
